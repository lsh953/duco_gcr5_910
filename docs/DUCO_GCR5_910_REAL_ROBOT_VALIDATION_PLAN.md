# DUCO GCR5-910 实机验证方案（不含执行）

- 适用范围：`duco_gcr5_910_ros2_ws` 双轨迹 Action 代理节点（`duco_ros_driver`）＋ MoveIt ＋ Gazebo 数字孪生
- 对应分支：`integration/round3-safety-fixes`
- 文档性质：**测试计划与风险控制措施**。本文档**不授权**任何实机运动。
- 授权状态：**未授权**。任何涉及真实机械臂运动、真实急停、真实断连、真实停止、真实恢复的操作，
  必须在现场安全条件、设备权限、人员职责确认后，由现场负责人**单独书面授权**方可执行。
- 编制原则：
  1. 所有异常场景**优先**用 mock 驱动与 Gazebo 覆盖；实机只验证"仿真无法证明"的部分。
  2. 凡是"命令机械臂做某动作"的步骤，都必须有独立于本软件的物理急停可用且有人值守。
  3. 任何一步出现不可解释现象，立即中止后续步骤（见 §11）。

## 2. 测试前风险评估

### 2.1 风险清单

| ID | 风险 | 触发场景 | 后果 | 缓解措施 |
|---|---|---|---|---|
| R-01 | 机械臂发生非预期运动 | 参数错误、目标越界、控制器状态异常 | 碰撞/夹伤 | 低速、小行程、空载、围栏内、手扶急停 |
| R-02 | 机械臂**不可控地继续运动** | 取消/停止请求未被确认（本软件无法证明已停止） | 持续运动至限位 | 物理急停为唯一可靠手段；测试前确认急停链有效 |
| R-03 | 停止请求发出但机械臂不停 | 厂商未提供停止确认接口 | 同上 | 同上；并把"网络断开"也作为停止手段预案 |
| R-04 | 轨迹越界/超速 | 规划结果异常 | 碰撞 | 限制关节范围与速度、`min_real_trajectory_points` |
| R-05 | 联锁未如预期锁住 | 落盘失败、目录不可写 | 未知状态被当成安全 | T-05 专测；`real_persistence_required=true` |
| R-06 | 联锁被意外解除 | 误调 `clear_fault` | 带着未知状态继续运动 | 恢复默认关闭；仅在受控用例中开启 |
| R-07 | 断连后软件状态与实际不一致 | 控制器断连/反馈丢失 | 误判完成或误判停止 | T-07/T-08 专测；默认按"不确定"处理 |
| R-08 | 反馈通道延迟/抖动导致误判 | 网络/驱动刷新率 | 误报成功或误报失败 | 记录实际刷新率；必要时放宽 `real_*_max_age` |
| R-09 | 复位动作撞上残留运动 | 人工恢复时机械臂仍在动 | 碰撞 | 恢复前必须目视确认静止（§10） |
| R-10 | 日志/证据缺失无法复盘 | 未同步记录 | 无法验收 | §12 记录要求；诊断话题全程录制 |
| R-11 | 上位机自动重试造成连续下发 | 上位机逻辑 | 连续运动 | §2.3（接口文档 §4）已要求禁用；测试时监控命令话题频率 |

### 2.2 版本相关风险

- MoveIt 版本变化会改变"取消超时 ⇒ 客户端错误码"的映射
  （2.12.3：`ABORTED → CONTROL_FAILED(-4)`；此前行为为 `CANCELED → PREEMPTED(-7)`）。
  现场若使用不同 MoveIt 版本，**必须先**按接口文档 §2.2 重新核对映射，再开始实机验证。

### 2.3 前置结论（必须成立才能进入实机）

1. 模拟驱动 + Gazebo 覆盖的异常场景全部通过（见 §2.4）。
2. 接口文档《双轨迹 Action 上游接口兼容性说明与升级说明》的 §6 检查清单已完成。
3. §3 的硬件安全防护检查全部通过。
4. 现场负责人书面授权。

### 2.4 已由 mock / Gazebo 覆盖、**不在实机重复**的场景

| 场景 | 覆盖方式 | 证据 |

| 取消成功 → `CANCELED` | Gazebo 端到端（孪生 Phase B S2） | `verify_all.sh` |

> 只在现场安全负责人确认无人处于危险区、且机械臂处于安全姿态时执行。

| ID | 检查项 | 方法 | 通过标准 | 执行人 |
|---|---|---|---|---|
| S-01 | 控制柜面板急停 | 按下（人在危险区外） | 伺服断电/机械臂立即停止；面板指示正确 | 安全负责人 |
| S-02 | 示教器急停 | 同上 | 同上 | 操作员 |
| S-03 | 附加急停（若有） | 同上 | 同上 | 安全负责人 |

| S-05 | 安全围栏/光栅联锁（若有） | 遮断光栅 | 进入安全状态 | 安全负责人 |
| S-06 | 急停复位流程 | 复位后重新使能 | 需人工复位且不自动恢复运动 | 安全负责人 |
| S-07 | 独立断电手段 | 演练操作 | 可在数秒内切断动力 | 安全负责人 |

**门槛**：S-01 ~ S-10 全部通过且记录留档，方可进入 §4。

## 5. 轨迹正常执行验证（T-02）

| 项 | 内容 |
|---|---|
| 目的 | 验证"真实完成"能被正确确认，以及未确认时不会被误报成功 |
| 前置 | T-01 通过 |
| 分步 | **T-02a**：`wait_for_real=true`，目标为小行程且可稳定到达 → 期望 `SUCCEEDED` 且诊断 `real=confirmed`、联锁释放<br>**T-02b**：`wait_for_real=true`，目标为**不可达/超出容差**的位置 → 期望**不报成功**（`ABORTED`）、`error_string` 非空、联锁**保持锁定**、后续真实目标被拒绝<br>**T-02c**：`wait_for_real=false`，仿真报成功 → 期望 Action 可报 `SUCCEEDED`，但诊断 `real=unconfirmed`、联锁**仍锁定** |
| 期望 | 三种情况均与文档一致；无"以仿真成功代替真实完成"的现象 |
| 中止条件 | T-02b 报成功（**严重**：立即中止全部测试） |
| 证据 | 结果状态、`error_code`、`error_string`、诊断话题、命令话题、录像 |
| 风险 | R-04、R-05 |

> **T-02b 是本方案最重要的一条**：它检验系统在"真实结果未知/未达标"时
> 是否会诚实地报告失败并保持联锁。

## 6. 取消与软件停止请求验证（T-03）

> 本节涉及"请求机械臂停止"，属于高风险操作。执行时机械臂必须处于低速、小行程、
> 无人靠近的状态，且操作员手按急停。**本节不执行**，仅列出计划。

| 子项 | 目的 | 步骤要点 | 期望 |
|---|---|---|---|
| T-03a | 正常取消 | 低速运动中请求取消；记录终止状态、`error_code`、`error_string`、诊断 | `CANCELED`（若厂商/控制器确实回报终止）；诊断与日志一致 |
| T-03b | 取消但无终止回报 | 使取消请求得不到终止状态（例如**受控地**阻塞/延迟仿真侧回报；实机侧如无法安全构造则**跳过并注明**） | 超时后 `ABORTED` + `-5` + `error_string` 含 `timed out`/`may still be executing`；联锁置为**不确定**；后续真实目标被拒绝 |
| T-03c | 取消被拒 | 使取消请求被拒绝（如可行） | 不是干净取消；联锁保持 |
| T-03d | 软件停止请求 | `publish_real_stop_request` 生效，观察真实通道收到的停止指令与机械臂实际行为 | 记录**实际**行为；**不得**据此宣称"机械臂已停止" |

**风险**：R-02、R-03（最高风险）。
**强制措施**：物理急停在手；机械臂低速小行程；全程录像；
若 T-03b/T-03c 无法在不危及安全的前提下构造，**允许跳过并如实记录为"未覆盖"**。

## 7. 控制器断连及反馈丢失验证（T-04）

| 子项 | 目的 | 步骤要点 | 期望 |
|---|---|---|---|
| T-04a | 反馈丢失 | 运动中阻断真实反馈话题（安全做法：停掉发布端或屏蔽网络，见 §11 中止条件） | 反馈超龄后**不报成功**；联锁按未确认处理；`error_string` 反映原因 |
| T-04b | 状态丢失 | 阻断 `robot_state` 话题 | 状态超龄后视为不健康；不报成功 |
| T-04c | 控制器断连 | 断开机械臂/控制柜通信 | 记录**实际**行为；软件必须把它当作"结果未知"而非"已停止"；联锁保持 |
| T-04d | 断连后重连 | 恢复通信 | 联锁**不自动**解除；诊断与日志一致 |

**风险**：R-03、R-07。
**强制措施**：只使用"可安全恢复"的断连方式（网线/进程），不使用控制柜总断电；
断连期间操作员手按急停；若实测断连后机械臂继续运动，立即急停并终止测试。

## 8. 故障联锁验证（T-05）

| 子项 | 目的 | 步骤要点 | 期望 |
|---|---|---|---|
| T-05a | 真实故障锁存 | 制造**安全的**真实故障（优先用可复位的方式，如驱动报错/状态不健康） | 目标被中止（`ABORTED`）；`latch_on_real_fault=true` 生效；后续真实目标被拒绝 |
| T-05b | 落盘不可写则拒绝真实运动 | 把 `fault_latch_file` 指向**不可写**路径（或在启动后使目录不可写），`real_persistence_required=true` | 启动后诊断 `persistence=unavailable`；发布真实轨迹被**拒绝**；日志有明确 ERROR；机械臂**不**运动 |
| T-05c | 落盘运行期写失败 | 运动中使状态目录变为不可写 | 拒绝继续下发真实命令；状态与日志一致 |
| T-05d | 联锁与仿真无关 | 纯仿真模式下制造真实侧故障 | 不影响纯仿真目标 |
| T-05e | 诊断字段 | 全程读取诊断话题 | `state=`/`latched=`/`sim=`/`real=`/`persistence=`/`reason=` 与日志一致 |

**风险**：R-05、R-06、R-11。
**说明**：**本联锁是软件联锁，不是硬件安全功能**，不得作为人身安全防护的替代。

## 9. 节点重启后的联锁保持验证（T-06）

| 子项 | 目的 | 步骤要点 | 期望 |
|---|---|---|---|
| T-06a | 重启后仍锁定 | 在联锁锁定的状态下**停止并重启**节点（正常关闭） | 启动后从状态文件恢复锁定；新真实目标被拒绝；诊断 `latched=1` |
| T-06b | 强杀后仍锁定 | 用 `kill -9` 强杀后重启 | 同上（这是落盘设计的目标场景） |
| T-06c | 上位机重启/断电后 | 上位机重启（若允许） | 同上 |
| T-06d | 删除状态文件 | 删除状态文件后重启 | 行为必须**明确且记录**（当前实现：无记录则不恢复锁定）——现场须据此规定"禁止手工删除状态文件" |
| T-06e | 状态文件位置 | 检查实际路径 | 位于 `$XDG_STATE_HOME` 或 `~/.local/state` 下，**不在 `/tmp`** |

**风险**：R-05。**强制措施**：T-06d 之后必须重新做一次 §3 检查再继续。

## 10. 人工恢复操作流程（T-07）

> 本流程只在机械臂**已确认静止**、故障原因**已查明并消除**、且现场负责人同意后执行。

1. **确认静止**：目视 + 示教器/厂商界面确认机械臂无任何运动趋势。**不得**仅凭诊断话题判断。
2. **确认原因消除**：故障已清除（急停复位、状态恢复健康、通信恢复）。
3. **确认责任人**：由现场负责人指定本次恢复的操作人，并在记录中署名。
4. **调用恢复服务**：`ros2 service call /clear_fault std_srvs/srv/Trigger`（服务名按实际配置）。
5. **核对结果**：诊断话题 `latched=0`、`state=` 回到非锁定值；服务返回 `success: true` 及原因文本。
6. **失败即停**：服务返回 `success: false` 时**不得**反复重试；恢复原状并上报。
7. **验证释放**：发送一个**低速、小行程**目标，确认被接受且行为受控；若被拒绝，回到第 1 步。
8. **记录**：时间、操作人、原因、服务返回、前后诊断输出、录像时间点。

**禁止**：自动重试恢复服务；在没有目视确认的情况下恢复；
用"重发目标成功"当作"机械臂已停止"的证据。

| 子项 | 期望 |
|---|---|
| T-07a | 机器人不健康时调用恢复 → 被**拒绝**（`success: false`），联锁保持 |
| T-07b | 条件满足时调用恢复 → 成功，联锁释放 |
| T-07c | `fault_recovery_enabled=false` 时 → 服务不可用/被拒绝 |
| T-07d | 恢复与并发故障消息竞争 → 不得用"恢复成功"抹掉同时到达的新故障 |

## 11. 测试终止条件和异常处置

### 11.1 立即中止（全部测试）的条件

1. 机械臂发生**非预期运动**（方向、幅度、速度任一超出约定）。
2. 发出停止/取消后机械臂**继续运动**。
3. 真实结果未知或未达标时**上报了成功**。
4. 落盘不可用却**仍允许**发布真实轨迹。
5. 联锁锁定状态下**接受了**新的真实目标。
6. 出现烟雾、异味、异响、错误报警、结构异常。
7. 任何人进入围栏内或任何有效危险信号。
8. 关键证据（录像/日志/诊断）无法记录。

### 11.2 中止动作顺序

1. 按下**物理急停**（第一动作，不依赖软件）。
2. 断开动力（必要时）。
3. 清空危险区并保持封锁。
4. 保存全部日志与录像（`ros2 bag`、诊断话题、节点日志），**不要重启或清理**。
5. 由现场负责人判定是否可继续；任何"未解释"的现象必须解释清楚后方可继续。
6. 中止后如需继续，必须重新执行 §3 与 §4。

### 11.3 现象记录要求

对每个异常：记录时间戳、当时的关节角、发出的目标、终止状态、`error_code`、
`error_string`、诊断话题内容、机械臂实际行为（录像时间点）、以及处置动作。
